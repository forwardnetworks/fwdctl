# edit-internet-exclusions

## Intent

Once the internet node has a connection it owns every public address that is not located elsewhere. Public space a network uses internally and never advertises to an upstream would be treated as the internet. The internet node's **excluded
subnets** keep such prefixes off it so they are located by their internal route. The list lives on the internet node only, is not generated by an NQE query, and a write **replaces all of it**: this skill reads the current list, applies your
change to it, shows the whole list before and after, writes the result and reads it back. How to derive what to exclude: `plan-synthetic-device` (`reference/internet-node.md`, "Internal public address space").

## Inputs

`network_id` and one of: `add` and/or `remove` (lists of public CIDR blocks, changes to the current list), or `set` (the whole list; `[]` clears it). Optional: `backdate_snapshot_id` and `apply` (default false). Each entry is a CIDR with the host bits
zero (a bare address is a /32); a block lying entirely inside private, shared (100.64.0.0/10), loopback, link-local, documentation, benchmarking (198.18.0.0/15), multicast or reserved space (Forward's own list) is refused in the dry run, with EVERY such entry named, before anything is sent. A list taken from a routing-table dump often holds some: filter them first. See `schema.json`.

## Reading the list first

`inspect-topology` with `kind: external` and `device: internet` shows the current `excluded_subnets`; no dry run is needed to read it.

## Dry run

Without `apply: true` nothing is changed. The skill reads the internet node and returns `mode: dry_run` with one change (`before` and `after`, the whole list) and the entries added and removed.

## Procedure

1. Check the entries. Read the internet node: none modelled is **unknown**, nothing changed.
2. Compute the new list from the current one. Identical to the current list: **ok**, nothing changed.
3. Dry run: return the plan. With `apply: true`: write the whole list, then read it back; a different list is **failed**, never ok.

## Backdate (optional): apply it now

By default a change reaches the **next** processed snapshot. With `backdate_snapshot_id` the internet node's configuration is re-dated to that snapshot: that snapshot and **every later one are invalidated**, set to
UNPROCESSED. Forward does **not** reprocess them by itself: run `edit-snapshot-reprocess` for each one, then `edit-advanced-reachability` if internet exposure is needed (it only runs after a snapshot is PROCESSED). The
dry run lists them. Ask for it only when the person wants it applied now, and get approval of the backdate separately. It cannot be undone; the list change can.

## Undo

The change's `undo`: run this skill with `set` = the change's `before` (the whole prior list).

## Evidence

One `topology` item: `before`, `after`, `added`, `removed`, `mode`, `backdate` and, once applied, `held`.

## Output

The envelope in `schema/skill-result.schema.json`, with `mode` and `changes`.

## Limits worth stating

The skill cannot show how paths change: trace the flow before and after. Exclusions are **prefix-based** (no per-interface or per-device exclusion): an address that a collected interface carries is located on that interface before the internet node is considered, so excluding it does not hide it from an internet-addressable result (`plan-synthetic-device`, `reference/exposure.md`). An exclusion keeps a prefix off the internet node, it does not make it reachable. Clearing the list gives every kept-off prefix back to the internet node.

## Next actions

`inspect-topology` (kind external, device `internet`) to see the list; `investigate-reachability` to test a path.

## Running this skill

Give the inputs as one JSON object on stdin: `echo '{"network_id": "<id>", "add": ["198.18.0.0/16", "198.19.0.0/16"]}' | fwdctl run edit-internet-exclusions`.
It needs the `fwdctl` binary and `FORWARD_URL`, `FORWARD_USERNAME`, `FORWARD_PASSWORD` in the environment. Read `status`
(`ok`, `failed`, `unknown`, `error`), `mode` and the `limits`; `unknown` is never a pass. Add `"apply": true` only after the dry run was accepted.
